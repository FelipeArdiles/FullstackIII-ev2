Introducción
En el desarrollo de software, un sistema de control de versiones es una herramienta
imprescindible para gestionar cambios, facilitar la colaboración en equipo y asegurar la
calidad de los proyectos. Entre las opciones disponibles, Git se ha consolidado como el
estándar global, permitiendo a desarrolladores de todo el mundo trabajar de manera
organizada, eficiente y segura.
En esta sesión, profundizaremos en la importancia de Git en entornos de desarrollo
modernos, explorando sus fundamentos y aprendiendo a implementar estrategias de
branching. Estas estrategias no solo optimizan el flujo de trabajo en equipo, sino que
también son esenciales para prácticas avanzadas como la integración continua y la
automatización del despliegue, pilares clave para el éxito en proyectos ágiles y
escalables.

¿Por qué usar diferentes estrategias de Branching?
La gestión de ramas (branches) es crucial para organizar el desarrollo de funcionalidades, correcciones y experimentos
sin afectar la rama principal (main o master). Elegir la estrategia adecuada depende del tamaño del equipo, la frecuencia
de lanzamientos y la complejidad del proyecto.

Git: Git Flow
### Principios Clave
- Rama master (producción).

Git: Git Flow
### Pasos Relevantes
- Rama principal ( main).
- Crear rama por tarea (feature/ o similar).
- Realizar commits y probar.
- Abrir Pull Request.
- Hacer revisión de código ( Code Review).
- Merge a main una vez aprobado.
### Ventajas
- Óptimo para despliegues continuos (CD).
- Facilidad para colaborar con revisiones.
### Desafíos
- Puede volverse complejo con muchos Pull Requests simultáneos.

Git: Trunk-Based Development
### Enfoque Principal
- Una sola rama estable (“trunk” o main), commits frecuentes.
- Uso de feature flags para control de despliegues parciales.
### Buenas Prácticas
- Commits pequeños y frecuentes.
- Pruebas automatizadas para cada push.
### Beneficios
- Menor complejidad de fusión de ramas.
- Favorece DevOps e integración/entrega continua.

Git: Ventajas y desafíos de cada estrategia
Se enfatiza que la elección depende del contexto del proyecto y la cultura de desarrollo del equipo.
Estrategia Ventajas Principales Desafíos
Git Flow - Control robusto
- Claridad en releases y hotfix
- Configuración más compleja
- Requiere mayor disciplina
GitHub Flow - Simplicidad
- Ideal para integración continua
- Requiere revisiones constantes
- Puede saturarse con muchos PRs
Trunk-Based Dev - Integración rápida
- Favorece la CI/CD
- Gestión de conflictos en commit
- Requiere equipo disciplinado

## Conclusiones
El control de versiones, junto con una estrategia de branching bien elegida, no solo determina la
eficiencia operativa, sino que también es un factor clave para fomentar una colaboración fluida y
minimizar los riesgos en el desarrollo de software. Dominar Git y sus estrategias de branching no es
simplemente una habilidad técnica, sino una base para implementar prácticas de desarrollo robustas y
escalables que se adapten a proyectosde cualquier magnitud y complejidad.
Además, la capacidad de elegir y ajustar estrategias de branching según el contexto del equipo y el
proyecto garantiza flexibilidad y capacidad de respuesta ante los desafíos del desarrollo moderno. Estas
prácticas son fundamentales para integrar conceptos como la integración continua (CI), la entrega
continua (CD) y el trabajo en equipos distribuidos,que definen los entornos de desarrollo FullStack en la
actualidad.
