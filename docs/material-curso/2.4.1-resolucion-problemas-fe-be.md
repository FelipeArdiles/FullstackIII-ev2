Introducción
En la actualidad, el desarrollo FullStack requiere una comprensión sólida de las buenas
prácticas en frontend y backend. Para ello, es fundamental conocer y aplicar patrones de
diseño y patrones arquitectónicos que permitan resolver problemas comunes de manera

- Implementado en frameworks como Angular/Vue.js.
- Separa la lógica de negocio (ViewModel) de la vista.

Ejemplo 1: Problemas de Sincronización de Datos en el Frontend
### Contexto Común
- Múltiples componentes necesitan acceder y actualizar la misma información (por ejemplo, un carrito de compras
compartido).
- Un estado mal gestionado puede provocar comportamientos inconsistentes (por ejemplo, datos desactualizados en
diferentes secciones de la interfaz).
### Solución con Patrones de Diseño (Observer / Pub-Sub / Container-Presentational)
- Container/Presentational: Mantener la lógica de datos (fetch, actualización) en un “Container” y delegar la
presentación en componentes “Presentational”.
- Observer / Pub-Sub: Cuando un componente emite un evento de actualización, los demás componentes suscritos
se notifican automáticamente y actualizan su estado.
### Ventaja
- Al delegar la lógica de actualización en una única fuente de verdad (el Container), se asegura la consistencia de
datos.
- La comunicación mediante eventos (Observer) evita el acoplamiento excesivo entre componentes.

Ejemplo 2: Administración de Conexiones en el Backend
### Contexto Común
- Varios servicios del backend necesitan conectarse a la misma base de datos.
- Abrir múltiples conexiones o instancias puede generar conflictos, uso excesivo de memoria o bloqueos de
recursos.
### Solución con Patrones de Diseño (Singleton)
- Singleton: Asegura que haya una sola instancia de la conexión a la base de datos.
- Se implementa una clase que maneja la conexión y, en cada requerimiento, se reutiliza la misma instancia si ya
existe.
### Ventaja
- Optimiza los recursos y evita condiciones de carrera al tener un único punto de acceso a la base de datos.
- Centraliza la configuración y la gestión de la conexión, facilitando el mantenimiento.

Ejemplo 3: Conflictos de Fusión (Merge) en un Equipo
### Contexto Común
- Varios desarrolladores trabajan en diferentes funcionalidades que deben integrarse con rapidez.
- Los conflictos de fusión (merge conflicts) pueden retrasar el proyecto y generar errores difíciles de rastrear si no se gestionan
adecuadamente.
### Solución con Estrategias de Branching (GitFlow o GitHub Flow)
### • GitFlow
1. Rama principal master para versiones estables.
2. Rama develop para la integración de las nuevas funcionalidades.
3. Ramas de feature independientes para desarrollar cada nueva característica.
4. Integración controlada mediante Pull Requests y revisiones en develop.
### • GitHub Flow (más simple)
1. Una única rama estable (main).
2. Ramas de feature por cada tarea.
3. Pull Requests para revisión de cambios y merge a la rama principal.
### Ventaja
- Estandariza el proceso de integración, minimizando conflictos y facilitando la colaboración.
- Permite aislar y corregir errores críticos en ramas especiales (ej: hotfix) sin interrumpir el desarrollo de nuevas funcionalidades.

Conclusiones
Los patrones de diseño y los patrones arquitectónicos son piezas fundamentales para el
desarrollo Los patrones de diseño y patrones arquitectónicos son fundamentales para un
desarrollo eficiente y escalable, tanto en el frontend como en el backend. Su correcta
aplicación reduce la duplicación de esfuerzos y asegura soluciones organizadas que facilitan la
colaboración en equipo.
Por otro lado, las estrategias de branching permiten mantener un control claro sobre la
evolución del proyecto, fomentando flujos de trabajo ordenados y habilitando prácticas clave
como la integración continua (CI) y la entrega continua (CD).
Al aplicar estos conceptos, los equipos están mejor preparados para enfrentar desafíos,
adaptarse a cambios y ofrecer productos de alta calidad. Con esto, cerramos la sesión de
FullStack 3, invitándolos a seguir practicando y explorando en proyectos reales, donde estas
herramientas se convierten en la base del éxito.
